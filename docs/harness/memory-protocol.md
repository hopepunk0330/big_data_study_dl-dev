# 에이전트 메모리 프로토콜 (모든 에이전트 공용)

이 문서를 참조하는 모든 에이전트는 아래 규칙을 그대로 따른다. 자기 이름에 해당하는 폴더를 쓴다: `.claude/agent-memory/<자기-이름>/`.

## 파일 구조

- **`index.md`** — 절대 삭제하지 않는다. 한 줄 요약만 계속 누적한다("확인된 개념/역량" 목록). 아무리 쌓여도 부담 없게 한 줄로 유지한다.
- **`recent.md`** — 최근 상세 기록을 최대 5개까지 롤링 유지한다. 각 항목은 `### YYYY-MM-DD` 헤더로 시작. **같은 날 여러 라운드가 생기면 하나의 헤더 아래 몰아넣지 않고, 매 라운드마다 새 헤더를 만들어 뒤에 `(2)`, `(3)`...을 붙인다**(예: `### 2026-08-22`, `### 2026-08-22 (2)`, `### 2026-08-22 (3)`) — 헤더가 파일에 등장하는 순서는 항상 실제 시간 순서와 일치해야 한다. 이 규칙을 어기면(하나의 헤더 아래 여러 라운드를 하위 불릿으로 욱여넣거나, 헤더 순서와 실제 시간 순서가 어긋나면) 아래 "정리(prune) 규칙"이 "가장 오래된 항목"을 잘못 판단해 실제로는 최신인 라운드를 지워버릴 수 있다.

## 시작 시

**가장 먼저, 프로젝트 루트의 `CLAUDE.md`를 읽고 이 프로젝트의 규칙(개요, 폴더 구조, 코딩 규칙, 검증 명령, 금지 항목, 행동 지침)을 파악한다(2026-09-01 신설)** — 하위 에이전트(Task/Agent 도구로 디스패치된 서브에이전트)는 메인 세션과 달리 이 파일이 자동으로 로드된다는 보장이 없다. 이 문서를 참조하는 모든 에이전트에 공통 적용되는 규칙이므로 **일반적인 "CLAUDE.md를 먼저 읽어라"는 지시**는 각 에이전트 파일에 되풀이하지 않고 여기 한 곳에 둔다. **다만 그 에이전트에만 해당하는 제약이 붙는 경우는 예외로 개별 명시를 허용한다**(2026-09-01 추가) — 예: `dl-expert.md`는 "환경 구성·패키지 설치는 `ml-project-workflow.md` 0절보다 `CLAUDE.md`를 따른다"는 도메인 고유 우선순위를, `full-stack-engineer.md`는 "검증 명령 값을 자기 파일에 복제하지 말고 매번 `CLAUDE.md`에서 직접 읽는다"는 지시를 각각 갖고 있다. **이런 항목은 중복이 아니라 공통 규칙이 담지 못하는 정보이므로, "중복 제거"를 이유로 삭제하지 않는다** — `CLAUDE.md`에 적힌 금지 항목(secrets 파일 미수정, push 전 허락 등)이나 프로젝트별 컨벤션(코딩 스타일, 상수 관리 방식 등)을 모르는 채로 작업하면 하네스 다른 규칙과 충돌하는 결과를 낼 수 있다.

그다음, 자기 폴더의 `index.md`와 `recent.md`를 읽어서, 이 사용자/이 프로젝트에 대해 이미 뭘 알고 있는지 파악한다.

**근거**: 2026-09-01, 이 하네스가 순수 DL 스터디 저장소(`big21/dl-dev`)로 포크된 뒤 `dl-expert`가 그 프로젝트의 `CLAUDE.md`를 전혀 참조하지 않는다는 게 실제 사용 중 발견됐다 — 어떤 에이전트 정의 파일도 "CLAUDE.md를 읽어라"고 명시하지 않고 있었다(모든 에이전트가 참조하는 `memory-protocol.md`에도 이 지시가 빠져 있었다). 메인 세션은 시스템 프롬프트가 `CLAUDE.md`를 자동으로 로드해주지만, 서브에이전트는 그 보장이 없어 명시적으로 지시해야 한다는 걸 이 사고로 확인해 신설했다.

## 기록 시점

의미 있는 순간(새 개념을 가르쳤다, 사용자가 뭔가를 헷갈려했다, 중요한 리뷰·감사를 했다, 재발하면 안 되는 실수를 발견했다) 후에 `recent.md`에 새 항목을 추가한다. 대화에서 알 수 있는 현재 날짜를 쓴다.

## 정리(prune) 규칙

`recent.md`의 항목이 6개가 되면:
1. 가장 오래된 항목의 핵심을 한 줄로 요약한다.
2. 그 한 줄을 `index.md` 맨 아래에 추가한다.
3. 그런 다음에만 `recent.md`에서 그 항목을 삭제한다.

**오래됐다고 요약 없이 그냥 버리지 않는다** — 디테일은 사라져도 "그런 일이 있었다"는 사실은 `index.md`에 반드시 남긴다.

## 하네스를 새 프로젝트로 포크할 때

`.claude/agent-memory/`의 **내용**(실제로 쌓인 파일명·수치·세션 이력)은 이식 대상이 아니다(`git-workflow.md` 2절) — 새 프로젝트로 그대로 복사하면 에이전트가 시작 시 그 내용을 지금 프로젝트의 맥락인 것처럼 읽고 착각한다. 그러나 **빈 템플릿(스캐폴드) 자체는 하네스의 일부이므로 이식 대상이다.**

- 하네스를 포크할 때(`.claude/agents/`, `.claude/skills/`, `docs/harness/`를 복사할 때), 그 시점에 `.claude/agents/`에 존재하는 에이전트마다 `.claude/agent-memory/<에이전트명>/index.md`·`recent.md`를 **Claude가 직접 새로 만든다** — 실제 이력 내용은 절대 복사하지 않고, "파일 구조" 절 형식(안내문 + "## 확인된 개념/역량" 헤더, 그 아래는 빈 채로)만 갖춘 빈 템플릿으로 만든다.
- 즉 새 프로젝트에서 각 에이전트는 "폴더째 없는 상태"가 아니라 **"내용만 초기화된 빈 폴더가 있는 상태"**로 시작한다 — 폴더가 아예 없으면 언제 만들어야 하는지 애매해지지만, 빈 템플릿을 미리 만들어두면 그 에이전트가 처음 실행될 때 바로 `recent.md`에 첫 항목을 추가하기만 하면 된다.
- `.claude/agent-memory/`는 `.gitignore`에 반드시 포함시킨다(이 프로젝트의 관례) — 이렇게 하면 이 폴더는 애초에 `harness` 브랜치 git 이력에 올라가지 않으므로, 하네스를 원격(예: 하네스 전용 GitHub 저장소)에 push해도 다른 프로젝트의 세션 이력이 실수로 함께 올라가거나 덮어써지는 일이 구조적으로 방지된다.
